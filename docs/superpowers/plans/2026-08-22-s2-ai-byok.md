**Mục tiêu:** Cho người học hỏi AI về chương đang đọc và "đào sâu" một đoạn bôi đen, bằng **key của
chính họ**, sao cho key **không bao giờ** đi qua máy chủ của chúng ta — và điều đó được **cưỡng chế

**Kiến trúc:** Key sống trong một `<iframe>` ở **origin riêng** (`vault.<domain>`), giao tiếp với

khác — nên một course hạng `interactive` bị duyệt sót vẫn **không đọc được key**. Trang chính không
bao giờ thấy key; nó chỉ gửi lời nhắc và nhận về dòng chữ trả lời.

**Tech stack:** React 19 + Vite (hai dev server, hai cổng = hai origin), TypeScript, `fetch` +
`ReadableStream` cho streaming (không thư viện SDK), Go/Fiber cho phần cưỡng chế phía server.

**Spec:** `docs/superpowers/specs/2026-08-20-platform-v2-design.md` §3 (và §1.4 cho lời hứa
không-key-trên-server).

## Ba hiệu chỉnh spec — tiền kiểm trên mã thật ngày 2026-08-22

Kế hoạch này **sửa** spec ở ba chỗ. Người thực thi đọc cả hai, nên phải biết chỗ nào kế hoạch thắng.

### HC-1. Chốt bảng Dexie đã mạnh hơn spec mô tả

Spec §3.2 viết: *"`db/local.test.ts` assert database có đúng 4 bảng — thêm bảng thứ 5 phải sửa con
số đó một cách có ý thức."*

**Thực tế:** database hiện có **5 bảng** (`annotations`, `meta`, `outbox`, `packages`, `progress` —
`packages` do Task 7 của hệ 1 thêm, ở `this.version(2)`). Và chốt ở `apps/web/src/db/local.test.ts:206`
**không đếm số, nó liệt kê tên**:

```ts
it('has exactly five tables, and they are the five this file knows about', () => {
  expect(db.tables.map((t) => t.name).sort()).toEqual([ /* năm tên */ ]);
```

Chú thích ngay trên nó đã nói rõ vì sao `toHaveLength(5)` là yếu hơn. Đây là **tin tốt**: muốn thêm
một bảng `keys` thì phải **gõ chữ `keys` vào danh sách** — không thể lọt bằng cách sửa một con số.

**Hệ quả cho kế hoạch này: chúng ta KHÔNG thêm bảng nào.** Key không nằm trong Dexie của trang
chính, dù ở bảng nào. Nó nằm trong `localStorage` của **origin khác**. Chốt trên vẫn phải xanh với
đúng năm tên sau khi hệ thống con 2 xong — đó là một trong các nghiệm thu của Task 4.

### HC-2. "Quét route" như spec mô tả KHÔNG tự cưỡng chế được gì

Spec §3.2 đòi: *"quét toàn bộ route đã đăng ký và khẳng định không route nào nhận trường mang key"*.

**Thực tế:** server là Fiber; 12 route đăng ký ở `apps/api/internal/server/server.go` (dòng 176–263).
`app.GetRoutes()` trả về **method, path, tên handler** — nó **không** biết handler đọc trường nào
từ body. Một handler nhận `{"api_key": "..."}` trông y hệt một handler không nhận, dưới con mắt của
bảng route. Test viết theo đúng chữ của spec sẽ **luôn xanh** và **không chặn gì** — tức là một cổng
mù thứ năm, đúng họ với bốn cái đã ghi trong `docs/carried-forward.md`.

**Thay bằng hai phép quét ở tầng nguồn** (Task 4), vì có **đúng hai** đường để key đi qua server:

| Đường | Phép quét cưỡng chế |
|---|---|
| Client **gửi** key lên server | Quét AST Go: không struct nào bị bind từ body có trường tên `api_key`/`apiKey`/`key`/`token`/`authorization`/`x-api-key` |
| Server **gọi** nhà cung cấp | Quét nguồn Go: không xuất hiện host nhà cung cấp nào (`api.openai.com`, `api.deepseek.com`, `api.anthropic.com`, `openrouter.ai`, `api.groq.com`) |

Cả hai hiện **xanh trên nền sạch** — đã kiểm ngày 2026-08-22: không tệp Go nào chứa các host trên,
không mã AI nào tồn tại trong repo. Đó là hình dạng đúng của một dây bẫy: nó xanh từ đầu, và chỉ đỏ
khi ai đó mở lại đường ta đã đóng.

### HC-3. Kho khoá chặn TRỘM key, KHÔNG chặn DÙNG key — spec chưa nói điều này

Đây là phát hiện quan trọng nhất của tiền kiểm, và spec không đề cập.

Iframe khác origin chặn được việc course độc đọc key. Nhưng course độc **chạy trong trang chính**,
và trang chính **được phép** `postMessage` cho kho khoá. Nên course độc vẫn có thể **bảo kho khoá
gọi hộ** — kinh điển là lỗi *confused deputy*. Nó không lấy được key, nhưng nó có thể:

- đốt tiền của người dùng bằng vô số lời gọi;
- **gửi nội dung ghi chú riêng tư của người dùng đi** dưới danh nghĩa lời nhắc.

Cái thứ hai nghiêm trọng hơn cái thứ nhất, và nó **không** được giải quyết bởi kiến trúc origin
riêng. Nói thẳng ra ở đây để không ai tưởng hệ thống con này đã đóng lỗ đó.

**Giảm thiểu trong phạm vi kế hoạch này (Task 9), không phải khắc phục triệt để:**
- kho khoá **tự giới hạn tần suất** (token bucket), không tin trang chính;
- **nhật ký hoạt động người dùng xem được** — mọi lời gọi, kèm thời điểm và số ký tự đã gửi;
- lời gọi đầu tiên của mỗi phiên cần **một cú bấm xác nhận trong khung kho khoá** (cú bấm đó xảy ra
  ở origin của kho khoá, nên JS trang chính không giả được).

**Khắc phục triệt để nằm ngoài hệ này** và phải ghi vào `docs/carried-forward.md`: chừng nào course
hạng `interactive` còn chạy cùng origin với ứng dụng, nó còn là *deputy*. Đường ra thật là cho
course chạy trong iframe sandbox origin riêng — spec §1.2 đã cân nhắc và **bác bỏ** vì nó phá P2
(chú thích cần chạm DOM chương). Đây là **đánh đổi có ý thức**, không phải thiếu sót; nhưng nó phải
được ghi ra chứ không nằm im.

## Global Constraints

Áp cho **mọi** task dưới đây.

- **Key không bao giờ rời origin kho khoá.** Không lên server, không sang trang chính, không vào
  Dexie, không vào outbox, không vào log. Nếu một task cần key ở trang chính để làm việc gì đó →
  thiết kế sai, dừng và báo.
- **Không đường dự phòng qua server.** Nhà cung cấp không cho gọi từ trình duyệt thì **không được
  hỗ trợ**. Đây là chỉ thị trực tiếp của người dùng, đã nhắc lại hai lần.
- **`postMessage` phải luôn có `targetOrigin` tường minh.** `'*'` bị cấm tuyệt đối ở cả hai chiều.
  Bên nhận phải kiểm `event.origin` trước khi đọc `event.data`.
- **Key theo từng thiết bị**, không đồng bộ. Mất máy này không lộ key ở máy kia.
- Dexie giữ nguyên **đúng năm bảng**. Chốt `local.test.ts:206` phải xanh khi hệ này xong.
- Origin kho khoá lấy từ **cấu hình build**, không hardcode. Dev: `http://localhost:5174`.
  Prod: `https://vault.<domain>`.
- **TDD thật:** test đỏ trước, dán RED vào báo cáo.
- `rtk` không trung thực (in "Success" cho lệnh exit 1, viết lại `cat`/`grep`/`find`, bọc
  `make test-e2e` rồi trả mã thoát của chính nó). Dùng `/bin/cat`, `/usr/bin/grep`, `/usr/bin/git`,
  `rtk proxy`.
- `vitest --reporter=basic` **không tồn tại ở vitest 4** — ném `ERR_LOAD_URL` rồi **thoát 0**.
- **`apps/web/e2e/**` không được `tsc` kiểm** (nợ đã ghi). Lỗi kiểu trong e2e không cổng nào bắt.

```ts
// apps/vault/src/protocol.ts
/** Tăng khi hình dạng thông điệp đổi theo cách không tương thích ngược. Bên nhận
 *  từ chối phiên bản lạ thay vì đoán — một trang chính cũ gặp kho khoá mới phải
 *  hỏng ồn ào, không được im lặng gửi sai. */
export const PROTOCOL_VERSION = 1 as const;

export type VaultRequest =
  | { v: 1; id: string; kind: 'listProviders' }
  | { v: 1; id: string; kind: 'status' }
  | { v: 1; id: string; kind: 'chat'; providerId: string; model: string;
      messages: Array<{ role: 'system' | 'user' | 'assistant'; content: string }> };

export type VaultResponse =
  | { v: 1; id: string; kind: 'providers'; providers: Array<{ id: string; label: string }> }
  | { v: 1; id: string; kind: 'status'; configured: boolean; providerId?: string; model?: string }
  | { v: 1; id: string; kind: 'chunk'; text: string }
  | { v: 1; id: string; kind: 'done' }
  | { v: 1; id: string; kind: 'error'; code: VaultErrorCode; message: string };

/** Mã lỗi là một union đóng, không phải chuỗi tự do: trang chính phải phân biệt được
 *  "chưa cắm key" (hiện lời mời cấu hình) với "nhà cung cấp từ chối" (hiện lỗi thật). */
export type VaultErrorCode =
  | 'not_configured' | 'bad_key' | 'rate_limited' | 'provider_error'
  | 'needs_consent' | 'unsupported_provider' | 'protocol_version';

export function isVaultResponse(x: unknown): x is VaultResponse {
  return typeof x === 'object' && x !== null
    && (x as { v?: unknown }).v === PROTOCOL_VERSION
    && typeof (x as { id?: unknown }).id === 'string'
    && typeof (x as { kind?: unknown }).kind === 'string';
}
```

```ts
// apps/vault/src/main.ts
import { PROTOCOL_VERSION, type VaultRequest, type VaultResponse } from './protocol';

export interface HandlerDeps { allowedOrigin: string }

/** Tách khỏi `addEventListener` để test gọi thẳng được. Trả về void: mọi hồi đáp
 *  đi qua `event.source.postMessage`, vì đó là đường duy nhất tới đúng khung đã hỏi. */
export function handleMessage(event: MessageEvent, deps: HandlerDeps): void {
  // Kiểm origin TRƯỚC KHI đọc data. Một thông điệp từ origin lạ không được
  // ảnh hưởng tới bất cứ gì, kể cả gây ra một hồi đáp lỗi — hồi đáp lỗi cũng là
  // một kênh thông tin.
  if (event.origin !== deps.allowedOrigin) return;

  const req = event.data as Partial<VaultRequest>;
  if (!req || typeof req !== 'object') return;
  const source = event.source as WindowProxy | null;
  if (!source) return;

  const send = (res: VaultResponse) => source.postMessage(res, deps.allowedOrigin);

  if (req.v !== PROTOCOL_VERSION) {
    if (typeof req.id === 'string') {
      send({ v: PROTOCOL_VERSION, id: req.id, kind: 'error', code: 'protocol_version',
             message: `Kho khoá dùng giao thức v${PROTOCOL_VERSION}.` });
    }
    return;
  }
  if (typeof req.id !== 'string') return;

  switch (req.kind) {
    case 'listProviders':
      send({ v: 1, id: req.id, kind: 'providers', providers: [] }); // Task 3 điền
      return;
    default:
      send({ v: 1, id: req.id, kind: 'error', code: 'unsupported_provider',
             message: 'Chưa hỗ trợ.' });
  }
}

if (typeof window !== 'undefined' && !import.meta.env.VITEST) {
  const allowedOrigin = import.meta.env.VITE_APP_ORIGIN as string;
  if (!allowedOrigin) throw new Error('VITE_APP_ORIGIN bắt buộc — kho khoá từ chối chạy khi không biết tin ai.');
  window.addEventListener('message', (e) => handleMessage(e, { allowedOrigin }));
}
```

```ts
// apps/vault/src/keystore.ts
export interface StoredConfig { providerId: string; model: string; apiKey: string }

/** Một khoá duy nhất, không tiền tố động: kho khoá là ứng dụng một-mục-đích ở
 *  origin riêng, nên không có ai khác để tranh chỗ. Đặt tên tường minh để người
 *  dùng mở DevTools thấy ngay thứ mình đã cắm. */
const STORAGE_KEY = 'tuhoc.vault.config';

export function readConfig(): StoredConfig | null {

        || typeof p.apiKey !== 'string') return null;

    // chặn toàn bộ tính năng.
```

```ts
// apps/vault/src/providers/openaiCompatible.ts
/** Phân tích dòng sự kiện SSE. Bộ đệm là bắt buộc: `ReadableStream` cắt theo biên
 *  giới gói mạng, không theo biên giới dòng, nên một sự kiện có thể tới làm nhiều
 *  mảnh — kể cả đứt giữa dấu `\n\n` phân tách. */
export async function* parseSSE(stream: ReadableStream<Uint8Array>): AsyncIterable<string> {
  const reader = stream.getReader();
  const dec = new TextDecoder();
  let buf = '';
  try {
    for (;;) {
      const { done, value } = await reader.read();
      if (done) break;
      // `stream: true` giữ lại byte của ký tự UTF-8 bị cắt đôi giữa hai gói —
      // tiếng Việt có dấu là hai byte, nên bỏ cờ này sẽ sinh ký tự thay thế.
      buf += dec.decode(value, { stream: true });
      let sep: number;
      while ((sep = buf.indexOf('\n\n')) !== -1) {
        const raw = buf.slice(0, sep);
        buf = buf.slice(sep + 2);
        for (const line of raw.split('\n')) {
          if (!line.startsWith('data:')) continue;   // bỏ ": comment", "event:", "id:"
          const payload = line.slice(5).trim();
          if (payload === '[DONE]') return;
          try {
            const j = JSON.parse(payload) as { choices?: Array<{ delta?: { content?: string } }> };
            const t = j.choices?.[0]?.delta?.content;
            if (t) yield t;
          } catch {
            // Một sự kiện hỏng không được giết cả câu trả lời đang chảy.
          }
        }
      }
    }
  } finally {
    reader.releaseLock();
  }
}

import type { Provider } from './types';

/** Một hàm dựng, năm nhà cung cấp: cả năm đều nói đúng hình dạng OpenAI. Khác nhau
 *  chỉ ở host và model mặc định — nên gộp lại thay vì chép năm lần. */
export function openAICompatible(
  id: string, label: string, baseUrl: string, defaultModel: string,
): Provider {
  return {
    id, label, defaultModel,
    async *chat(req, key, signal) {
      const res = await fetch(`${baseUrl}/chat/completions`, {
        method: 'POST', signal,
        headers: { 'content-type': 'application/json', authorization: `Bearer ${key}` },
        body: JSON.stringify({ model: req.model, messages: req.messages, stream: true }),
      });
      if (res.status === 401 || res.status === 403) throw new ProviderError('bad_key', 'Key bị từ chối.');
      if (res.status === 429) throw new ProviderError('rate_limited', 'Nhà cung cấp giới hạn tần suất.');
      if (!res.ok || !res.body) throw new ProviderError('provider_error', `HTTP ${res.status}`);
      yield* parseSSE(res.body);
    },
  };
}

export class ProviderError extends Error {
  constructor(public code: 'bad_key' | 'rate_limited' | 'provider_error', message: string) {
    super(message);
    this.name = 'ProviderError';
  }
}
```

```ts
export async function* parseAnthropicSSE(stream: ReadableStream<Uint8Array>): AsyncIterable<string> {
  const reader = stream.getReader();
  const dec = new TextDecoder();
  let buf = '';
  try {
    for (;;) {
      const { done, value } = await reader.read();
      if (done) break;
      buf += dec.decode(value, { stream: true });
      let sep: number;
      while ((sep = buf.indexOf('\n\n')) !== -1) {
        const raw = buf.slice(0, sep);
        buf = buf.slice(sep + 2);
        for (const line of raw.split('\n')) {
          if (!line.startsWith('data:')) continue;
          try {
            const j = JSON.parse(line.slice(5).trim()) as
              { type?: string; delta?: { text?: string } };
            if (j.type === 'message_stop') return;
            if (j.type === 'content_block_delta' && j.delta?.text) yield j.delta.text;
          } catch { /* bỏ sự kiện hỏng */ }
        }
      }
    }
  } finally { reader.releaseLock(); }
}
```
